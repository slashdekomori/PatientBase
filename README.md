# PatientBase

Настольная программа для ведения реестра травматологических пациентов.
Русский интерфейс, Qt 6 Widgets, PostgreSQL. Рассчитана на работу в локальной
сети отделения: несколько рабочих мест подключаются к одному серверу, у
каждого отделения — своя база.

## Возможности

- карточка пациента: паспортные данные, анамнез, жалобы, локальный статус,
  показатели состояния, группа крови и Rh;
- диагнозы и операции с автодополнением по справочникам МКБ;
- консультации, манипуляции, анестезия, дополнительные обследования;
- лекарственные назначения с расчетом дозировки по возрасту и весу;
- вакцинации, АИГ, КОКАВ, физиопроцедуры;
- дневники наблюдений и рекомендации на выписку;
- поиск по случаям и пациентам, печать документов в `.docx` через `DocParser`;
- многопользовательская работа: одна база на отделение, общий сервер
  PostgreSQL.

## Состав репозитория

```
main.cpp                 точка входа

Common/                  общие виджеты, справочники МКБ, лекарства, константы
SQLTable/                слой работы с PostgreSQL
JSON/                    подготовка patient_data.json для DocParser
Sources_files/           справочники (МКБ, отделения, лекарства)

шаблоны_основных_документов/  шаблоны для DocParser
DocParser.bin/.exe       генератор документов (исходников в репозитории нет)

build_linux.sh           сборка и раскладка Linux-дистрибутива
BUILD_WINDOWS_RU.md      сборка под Windows
AGENTS.md                заметки по архитектуре и подводным камням
```

## Требования

- Qt 6 (Widgets, SQL), компилятор C++17;
- PostgreSQL 12+ на сервере;
- для Windows — Qt 6 MinGW 64-bit (см. `BUILD_WINDOWS_RU.md`).

## Сборка и запуск

### Linux

Системный `qmake` может быть от Qt 5 и не собрать проект — нужен именно
`qmake6`.

```bash
mkdir -p build-linux && cd build-linux
qmake6 ../PatientBase.pro
make -j"$(nproc)"
```

Или одной командой:

```bash
./build_linux.sh
```

Скрипт соберет программу и разложит `dist-linux/`: бинарник, `DocParser.bin`,
`settings.ini`, `Sources_files/`, `шаблоны_основных_документов/` и `Output/`.

Запускать нужно из папки дистрибутива: `patient_data.json` и документы
пишутся в текущий каталог.

### Windows

Подробная инструкция — [`BUILD_WINDOWS_RU.md`](BUILD_WINDOWS_RU.md). Кратко:
Qt 6.7.3 MinGW 64-bit, Release, затем `windeployqt`, рядом с `.exe` положить
`DocParser.exe`, `settings.ini`, `Sources_files/`,
`шаблоны_основных_документов/` и пустую `Output/`.

## Подключение к базе

`settings.ini` лежит рядом с программой (в репозитории — только шаблон):

```ini
[database]
host=<IP-сервера>
port=5432
name=travma
user=pb
password=<пароль>
```

`name` — база своего отделения. Без `settings.ini` или доступного PostgreSQL
программа запускается, но каждое сохранение падает.

## Сервер

Сервер PostgreSQL разворачивается скриптами из `server/`:

- **Debian / Ubuntu** — [`server/debian/README.md`](server/debian/README.md);
- **РЕД ОС 7.3 / 8** — [`server/redos/README.md`](server/redos/README.md);
- общая часть, несколько баз, бэкапы, обновление схемы —
  [`server/README.md`](server/README.md).

Один сервер и одна учетка обслуживают несколько отделений; у каждого — своя
база. Клиент выбирает базу только через `database/name` в `settings.ini`.

Схема таблицы `database` — `server/schema.sql` (346 столбцов). Она должна
совпадать с `SQLTable::table_columns_and_types` в `SQLTable/sqltable.h`:
если столбца нет в базе, все сохранения падают.

## Перенос старых данных

Старые версии хранили случаи в SQLite (`DataBase.db`). Перенос в PostgreSQL:

```bash
python3 server/migration/sqlite_to_csv.py /путь/к/DataBase.db
PGSSLMODE=require psql -h <IP-сервера> -U pb -d travma -f load_cases.sql
```

Подробно, с проверками и откатом — [`server/migration/README.md`](server/migration/README.md).

## Документы и печать

При печати программа формирует `patient_data.json` в текущем каталоге и
передает команду `read_json` процессу `DocParser`. Тот пишет `.docx` в
`Output/` (или `Output/ALL_HYSTORY/`). Логика шаблонов и верстки находится
только в бинарнике `DocParser`; в C++ меняются данные, которые он получает.
Без `DocParser` рядом с программой печать не работает.

## Данные пациентов

`DataBase.db`, `cases.csv`, `Output/` и дампы PostgreSQL содержат реальные
персональные данные. Не коммитьте их в git, не пересылайте в мессенджерах и
не оставляйте на общедоступных дисках. Для сервера обязательны регулярные
бэкапы (`server/backup.sh`).

## Проверка изменений

Автотестов и CI в проекте нет. Минимальная проверка после изменений:
сборка без ошибок и ручной смоук-тест — открыть случай, сохранить, создать
новый, найти по фамилии, напечатать документ.
